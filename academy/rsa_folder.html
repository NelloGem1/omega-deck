⬡ RSA Folder Lock — hybrid RSA-2048 + AES-256-GCM

🔑 The Idea — why hybrid?

RSA can't encrypt large data — it's slow and limited to ~245 bytes at 2048-bit. AES is fast but has the key-distribution problem. Hybrid solves both:

LayerAlgorithmJob
Bulk dataAES-256-GCMEncrypts every file with a fresh random key + nonce (authenticated — tamper-proof)
Key wrapRSA-2048-OAEPWraps the small AES key — RSA's only job
ManifestJSON (.flock)Records filenames/sizes/nonces so unlock rebuilds the tree

File format magic: FLOCK1\n header on every .enc file.

⚡ Commands

python folder_lock.py keygen                  # creates pub + priv PEM keys
python folder_lock.py lock <folder>           # encrypts every file in place → .enc
python folder_lock.py unlock <folder>         # restores files from .enc
python folder_lock.py ... --keydir DIR         # keys live somewhere else

🗝️ Key Rules

folder_lock_pub.pem — share freely (the "padlock"). Anyone can lock files to you.

folder_lock_priv.pem — KEEP SECRET. The only way in. Lose it = data gone forever. No backdoors, no recovery — that's the point.

🔬 How it works internally

keygen

Generates RSA-2048 keypair (public exponent 65537), writes both PEMs unencrypted.

lock

Walks the folder (os.walk), skips existing .enc/.flock files, and for each file:

  1. Fresh os.urandom(32) AES key + 12-byte nonce
  2. AESGCM.encrypt(nonce, data, None) → ciphertext+tag
  3. RSA-OAEP encrypt the AES key with the public key
  4. Write .enc: MAGIC + wrapped key + nonce + ciphertext
  5. Manifest .flock JSON maps original paths → enc metadata

unlock

Reverse: RSA-decrypt wrapped key with private key → AES-GCM decrypt → restore original bytes and names.

🛡️ Security notes

  • GCM gives authenticity — tampered ciphertext fails the tag check. Better than CBC+HMAC manual combos.
  • Fresh key+nonce per file — no nonce reuse (the AES-GCM killer we proved in crypto challenges).
  • 2048-bit RSA — factoring infeasible (we broke 191-bit in 17s; 2048 is ~10³⁸× harder).
  • No passwords — keys ARE the credentials. Back up priv.pem like a birth certificate.
  • In-place lock — originals are overwritten/deleted after encrypt. Test on a copy first.
